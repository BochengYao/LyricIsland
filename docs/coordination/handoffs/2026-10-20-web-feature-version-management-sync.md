# 新功能版本管理与前台同步修复交接

- 日期：2026-10-20
- 发布目标：`origin/main`（集成基线 `0459dea`）
- 范围：官网维护后台、新功能内容 API、ESA 运行时与契约/回归测试

## 问题

- “新功能内容”的版本候选错误依赖版本预告和既有条目，后台无法在当前页面独立创建或调整完整版本号，因此实际版本已经高于 `V3.3.0` 时仍被旧值卡住。
- 线上 `V3.3.0` 的 4 条内容均为隐藏状态。公开接口会过滤隐藏条目，因此前台版本选择器继续停留在 `V3.2.49`。
- ESA 公开接口没有返回独立版本元数据，后台与公开端无法稳定区分“空版本”和“尚未保存任何条目的版本”。

## 修复

- 恢复 `content.versions` 独立版本元数据；历史数据缺少该字段时，从已有条目安全恢复版本。
- 后台支持在“新功能内容”页创建、重命名、删除版本，并将重命名原子级联到该版本全部条目。
- 版本管理与“版本预告”彻底解耦，可直接输入任意规范 `vX.Y.Z` 版本，例如 `V3.3.8`。
- 当前版本明确显示隐藏条目数量，并提供“全部设为前台显示”；保存结果不再把仍有隐藏条目的状态误报成已经同步。
- Next 路由与 ESA 运行时保持同一套鉴权、校验和错误语义；非空版本删除必须显式确认级联。

## 兼容性

- 公开 `/api/features` 保持现有 summary/sections 结构，只补回 `content.versions`；公开页继续只展示 `visible: true` 的条目。
- `早期更新` 兼容组仍可读取、编辑和保存，并可一次性迁移到完整版本号。
- 版本号比较与查重不区分大小写，已有大小写形式保持可读。

- 代码部署后需在已登录后台选择线上 `V3.3.0`，重命名为实际版本号，并将需要公开的条目设为“前台显示”后保存。
- 生产验收须分别确认：提交已到远端 `main`、页面/API 返回 `Server: ESA`、公开 API 返回 `versions`、目标版本有可见条目且 `/updates` 出现该版本。
- 本任务使用隔离 worktree；主工作区现有未提交改动未触碰。
