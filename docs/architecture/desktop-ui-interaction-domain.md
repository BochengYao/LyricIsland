# Desktop UI & Interaction 领域知识

> 领域 Owner：Desktop UI & Interaction
>
> 本文记录桌面端长期架构、边界与设计原则。它不替代具体 Feature Task 的设计说明、验收记录或发布交接。

## 1. 领域使命与职责边界

Desktop UI & Interaction 负责 `LyricHover.App` 中用户可见的桌面体验：顶部动态岛、任务栏歌词浮层、WPF 窗口与控件、设置、引导、模块化布局、动画、主题、国际化和 UI Automation 可观察的交互。

本领域消费 Desktop Core 暴露的状态、命令与快照，并把它们转为可理解、稳定且可访问的界面；不在 View 或窗口代码中创造播放器、媒体会话、歌词、缓存、时间轴或播放状态的第二份真值。

以下能力属于其他领域：播放器发现与 SMTC 读取、歌词检索/解析/同步、时间轴规则、缓存、曲目匹配和播放状态语义属于 Desktop Core；官网和商店宣传资产分别属于 Web 与 Brand 领域。UI 如需新数据，应提出接口/DTO/snapshot/event/observable 需求，而不是绕过契约自行轮询或推导。

## 2. 当前核心架构

```text
Desktop Core
  immutable media / lyric / timeline state and commands
                     │
                     ▼
LyricHover.App composition root (MainWindow)
  settings lifecycle · display-state orchestration · window coordination
          ┌──────────┼───────────────┐
          ▼          ▼               ▼
  Island modules   Settings UI    Taskbar lyric surface
  (module host)    (WPF window)  (independent non-activating window)
```

- 应用是 .NET Core 3.1 WPF 桌面应用。`MainWindow` 是顶部岛的组合根：它协调 UI 生命周期、设置应用、岛状态和已注入服务，不能成为 Core 规则的复制品。
- 岛由 `Modules/IslandModuleHost` 承载。模块通过 `IIslandModuleView`、`IslandRenderState` 和 Core 布局模型渲染；歌词、封面、播放控制、歌曲信息、进度和分割线是可组合模块。
- 布局编辑由 `LayoutEditing/` 协调：工具箱卡片、拖拽负载、插入指示器、幽灵窗和编辑会话彼此分工。编辑的是草稿，保存时才提交设置。
- 设置模型为 `OverlayPlacementSettings`，经 `OverlaySettingsStore` 归一化、默认化、迁移和原子写入。设置窗口只编辑工作副本，并按 Apply/Save/Cancel 的语义回传。
- `UiLanguageService` 是桌面国际化入口；语言偏好持久化在 `OverlayPlacementSettings.Language`。
- 任务栏歌词采用独立的 LyricDock 窗口和控制器，消费同一份 `LyricsPresentationSnapshot`，与顶部岛独立启用但共享展示数据，不建立第二套媒体刷新、歌词解析或缓存链路。

## 3. 模块职责

| 模块 | 长期职责 | 不应承担的职责 |
| --- | --- | --- |
| `MainWindow` | 窗口组合、UI 生命周期、Core 状态到展示快照的映射、岛/设置/任务栏表面的协调 | 媒体发现、歌词解析、时间轴决策 |
| `Modules/` | 以统一渲染状态显示单一能力，处理模块内视觉与用户手势 | 按播放器名称分支业务策略、直接访问 SMTC |
| `LayoutEditing/` | 布局草稿、拖放、插入预览、排序、删除和撤销反馈 | 修改正式布局而不经保存、重写 Core 布局语义 |
| `PlacementSettingsWindow` | 设置导航、主题、语言、表单校验、确认与可操作提示 | 直接实现 Core 规则或静默改变兼容设置 |
| `LyricDock/` | Windows 11 任务栏窗口、屏幕/任务栏安全定位、Widgets 租约、失效关闭 | Explorer 注入、策略写入、提权、媒体轮询 |
| `Tutorial*` | 首次使用的遮罩、步骤、行动提示及可中断流程 | 覆盖真实播放/歌词快照，或阻塞正常退出 |

## 4. 关键技术选型

- **WPF + XAML**：页面层级、样式、模板、键盘可访问性和动画以 WPF 原生能力实现；优先扩展已有控件模板和资源键，避免为相似外观再建一套控件。
- **Core snapshot / UI state**：展示层以稳定 snapshot、事件或命令接口工作。UI 可产生展示性状态（例如动画进度、编辑草稿、悬停状态），但不保存业务真值。
- **模块化岛屿**：布局与模块实例配置分离；横向积木与自动折叠/展开布局相互独立，分割线是普通可拖动模块。
- **Windows 原生窗口能力**：任务栏歌词以 Win32/DWM/UI Automation 获取真实环境；使用非激活、无任务栏图标、无边框的轻量窗口，保持右键可用且左键无业务操作。
- **材质与主题**：设置窗口优先使用 Windows 11 系统材质能力与应用资源字典。Liquid Glass 只用于大面积容器、分区和层次，不把每一个按钮、输入框都做成玻璃；前景/边框/阴影必须随浅色、深色和系统主题保持对比度。
- **国际化**：简体中文、繁体中文、英语、日语和系统跟随通过集中服务映射。语言选择项以本国语言显示；共享控件的选择文本绑定到实际选项展示名，不能依赖 WPF 内部 `SelectionBoxItem`。

## 5. 已解决并应复用的经验

- **动态文本布局**：不同语言、翻译和支持文案长度不等。使用 Grid、可伸缩列、正常文档流、最小尺寸和换行/滚动策略；不得用绝对覆盖层遮住文本，也不得以静默截断替代信息架构。
- **设置控件一致性**：语言、播放器和歌词源下拉框共用选择模板；已选项必须即时可见。语言图标采用 `文 / A`，但仍保留本地化 ToolTip 与 AutomationProperties.Name。
- **国际化回退**：系统为 `zh-Hant`/`zh-TW`/`zh-HK` 时使用繁体中文，其他 `zh` 使用简体中文，`ja` 使用日语，未匹配语言回退英语；设置改变要立即重绘并持久化。
- **布局编辑可靠性**：跨窗口拖放必须有插入预览、操作去重和取消回滚；拖拽幽灵应随主题变化并以鼠标中心定位。保存、取消、恢复默认和意外关闭都有清晰且不同的语义。
- **材质可读性**：磨砂/云母效果不是简单半透明矩形。必须同时处理窗口背景、圆角裁切、DWM 边角、文字对比度和深浅主题，否则会出现白底直角残影、纯黑失材质或浅色文字低对比度。
- **任务栏 fail-closed**：安全性优先于展示。真实 Taskbar、Widgets、UIA 矩形、DPI、可用连续空间或刷新验证任一不可靠时，隐藏/关闭功能并恢复原 Widgets 状态，而不是猜测位置继续显示。

## 6. 已废弃或禁止的方案

- 在 UI 层重新轮询媒体会话、重新解析歌词、重新计算时间轴或创建独立缓存。
- 以固定保留宽度、固定 Widgets 尺寸、任务栏几何中心或本地化名称唯一匹配来放置任务栏歌词。
- 注入、替换或重启 Explorer；写组策略；提权；把 Widgets provider 当作任务栏歌词入口。
- 把教程文案混入真实播放快照或任务栏歌词表面。
- 用大背景复刻顶部岛到任务栏；任务栏歌词应是轻量的图标与歌词表面。
- 为了视觉统一将所有控件玻璃化、通过低对比文字营造“轻盈感”、或以裁剪代替响应式布局。
- 将历史 WebView/React 设置实验作为当前默认架构。当前主线为 WPF 设置 UI；任何替换必须以独立 Feature Task 评审协议、性能、可访问性、离线资源与迁移成本。

## 7. 不可破坏的兼容性要求

- 展示品牌：英文 `LyricHover`；中文可见品牌“歌词岛 | LyricHover”。
- 发布兼容标识不得因 UI 改动而变更：Store 包身份 `70643607.LyricIsland`、应用标识 `LyricsIsland`、单实例名 `LyricsIsland.DesktopLyrics.SingleInstance`。
- 数据目录必须保留从 `LyricsIsland` 和早期 `AppleMusicDesktopLyrics` 到当前 `LyricHover` 的迁移路径。
- 设置新增或改名必须有默认值、旧文件缺失值处理、升级行为、回滚说明和人工验收。任务栏歌词默认关闭，不能影响顶部岛既有体验。
- 任务栏歌词只面向 Windows 11：与顶部岛独立开关、可同时显示、沿用 `ScreenName`；当前用户的 `TaskbarDa` 只能按租约临时修改，必须精确还原 absent/0/1，不写策略、不提权、不重启 Explorer。
- 用户可访问性不可被视觉改造破坏：键盘焦点可见、图标控件有可读名称、按钮维持足够命中面积，左右键语义稳定。

## 8. 当前已知限制

- 任务栏歌词必须继续完成真实 Windows 11 矩阵验证：主/副屏、左/中对齐、不同任务栏密度、100–200% DPI、自动隐藏、全屏遮挡、Explorer 重启以及 Widgets 原状态 absent/0/1。自动测试不能替代这些系统交互验证。
- 液态玻璃的最终视觉取决于系统版本、窗口后台与 DWM 能力；不支持或无法可靠应用时应退化为高对比、圆角完整的实体主题，而非错误的半透明效果。
- 多语言扩展持续要求逐页检查长文本、按钮、链接、模块描述和教程。视觉截图不能替代真实控件的缩放、键盘导航与本地化验收。

## 9. 后续开发原则

1. 每个 Feature Task 先重读领域章程、既定决策、相关 Core 接口与回归基线；只在本领域边界内实现。
2. 先复用现有资源、控件模板、模块契约和状态入口；若需要新能力，新增清晰接口而不是复制实现。
3. UI 状态与业务状态分离：View 负责呈现、输入和短暂交互，Core 负责媒体/歌词/时间线真值。
4. 设计采用 Apple 风格的克制层级：清晰字体层级、连续圆角、统一间距、适量材质、少而有意义的阴影和反馈动画。
5. 动画必须可取消、与当前状态一致，并尊重省电模式；拖拽、窗口调整与歌词横滚不可因装饰效果造成卡顿。
6. 所有可变长度内容按最坏语言长度和 DPI 验证；优先重排、增长或滚动，绝不覆盖、裁断关键信息或挤压命中区。
7. 涉及 Windows Shell、Taskbar、Win32、DWM、UIA、多屏、DPI、Z-order 和焦点时，以真实环境探测为依据。未知即 fail-closed，并提供用户可操作的失败原因。
8. 每次完成 UI 修改都做 Release 构建、同构建桌面测试，以及与改动相称的手动 UI 验收；构建通过不等于实机交互通过。
