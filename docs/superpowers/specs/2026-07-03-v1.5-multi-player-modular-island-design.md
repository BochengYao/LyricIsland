# Lyric Island v1.5 多播放器与模块化歌词岛设计

- 日期：2026-07-03
- 状态：已完成交互确认，待书面规格复核
- 目标版本：v1.5
- 源码仓库：`D:\AppleMusicDesktopLyrics`

## 1. 背景

v1.0 已作为 Lyric Island 歌词岛上架 Microsoft Store，当前应用以 Apple Music 桌面歌词为主要场景，通过 Windows SMTC 读取播放状态，并使用既有歌词检索、缓存、匹配和 LRC 显示管线。

v1.5 将播放器入口从 Apple Music 场景扩展为通用 SMTC 会话，同时把现有固定歌词岛重构成可组合模块。首批明确适配：

- QQ 音乐
- 网易云音乐 UWP
- 酷狗音乐
- Spotify
- 酷我音乐

“适配成功”定义为：能够识别媒体会话、读取并清洗曲目信息、匹配同步歌词、显示播放进度，并在播放器声明支持时执行上一曲、播放/暂停和下一曲。播放器不提供可靠时间轴时，应用使用内部计时维持歌词同步。

## 2. 目标与非目标

### 2.1 目标

1. 使用原生 C# SMTC 服务持续监听 Windows 媒体会话，替代每秒启动 PowerShell 进程的读取方式。
2. 自动选择正在播放且最近活跃的会话，并允许用户锁定播放器。
3. 将播放器差异限制在配置与清洗策略层，不复制五套播放器连接器。
4. 提供两种独立布局模式：A“横向积木”和 C“双态展开”。
5. 允许用户从设置窗口把模块直接拖到屏幕顶部的真实歌词岛，并提供吸附、排序、删除、撤销和保存。
6. 首批提供歌词、专辑封面、播放控制、歌曲信息、播放进度和分割线模块。
7. 使用可自定义全局快捷键调整歌词偏移，不提供歌词偏移可视模块。
8. 在封面、时间轴、控制能力或歌词缺失时局部降级，不让整个岛失效。

### 2.2 v1.5 不包含

- 音量模块
- 收藏、喜欢或歌单操作
- 依赖播放器私有接口的插件
- 云端布局同步
- 从 Lyricify 或其他同类产品复制代码、图标、文案或视觉资源

## 3. 总体架构

采用“原生 C# SMTC 服务 + 统一状态快照 + 模块化渲染”的分层方案。

```text
Windows SMTC sessions
        |
        v
SmTcMediaSessionService
        |
        +--> SessionSelectionPolicy
        +--> PlayerProfileCatalog
        +--> TimelineCoordinator
        |
        v
NowPlayingSnapshot
        |
        +--> 现有歌词检索/缓存/匹配/LRC 管线
        +--> IslandModuleRegistry
        +--> 播放控制命令回送 SMTC
        |
        v
IslandLayoutRenderer (A / C 独立布局)
```

### 3.1 `SmTcMediaSessionService`

该服务在应用生命周期内持有 `GlobalSystemMediaTransportControlsSessionManager`，监听会话新增、移除、媒体属性、播放状态和时间轴变化。它负责：

- 枚举全部 SMTC 会话，而不只调用 `GetCurrentSession()`。
- 读取标题、歌手、专辑、封面、播放位置、时长、播放状态和 `SourceAppUserModelId`。
- 读取上一曲、下一曲、播放、暂停等控制能力。
- 向当前选中会话发送控制命令。
- 把 WinRT 异常转为稳定的应用状态，不把异常直接抛到 UI 刷新循环。

UI 不直接持有 WinRT 会话对象，只消费不可变的统一快照。

### 3.2 `NowPlayingSnapshot`

统一快照至少包含：

- 会话标识和来源应用标识
- 播放器显示名
- 标题、歌手、专辑
- 封面图像或封面缺失状态
- 当前播放位置和总时长
- 时间轴可靠性：`Reliable`、`Estimated`、`Unavailable`
- 播放状态
- 上一曲、播放、暂停、下一曲能力
- 媒体属性更新时间和播放状态更新时间

模块只读取该快照，不根据播放器名称写条件分支。

### 3.3 `SessionSelectionPolicy`

默认选择规则按优先级执行：

1. 用户锁定且仍存在的播放器会话。
2. 当前处于 `Playing` 且最近发生媒体属性或播放状态变化的会话。
3. Windows 报告的当前会话。
4. 最近暂停且仍具有有效媒体属性的会话。

用户锁定的会话消失后，锁定值保留但本次运行回退到自动选择；会话重新出现时恢复锁定。设置页提供“自动”和已发现播放器列表，不要求用户输入应用标识。

### 3.4 `PlayerProfileCatalog`

配置表按 `SourceAppUserModelId`、进程/包显示信息和运行时能力识别播放器，包含：

- QQ 音乐
- 网易云音乐 UWP
- 酷狗音乐
- Spotify
- 酷我音乐
- Apple Music（保留现有支持）
- 通用 SMTC 播放器

每个配置只定义来源别名、标题/歌手清洗策略和时间轴偏好。运行时能力始终优先于静态假设：即使某个版本通常缺少时间轴，只要本次会话提供持续更新且合理的时间轴，就使用真实时间轴。

未知 SMTC 播放器使用通用配置，因此新增播放器通常无需发布新版本。

## 4. 时间轴与歌词同步

### 4.1 `TimelineCoordinator`

时间轴协调器维护最后一次可信位置、采样时间和播放状态：

- 真实时间轴连续且范围合理时，直接使用播放器位置。
- 播放器处于播放状态但位置长期为零、缺失或停止更新时，切换到内部单调时钟估算。
- 获得新的可信位置后，差值小于 1.5 秒时在短时间内平滑校准；差值达到 1.5 秒时立即跳转，避免歌词长期错位。
- 暂停时冻结估算位置；恢复播放后从冻结位置继续，直到真实位置重新可用。
- 用户在播放器中手动跳转且真实位置变化明显时，立即更新歌词位置。

播放进度模块在估算模式下显示 `≈` 标记，不伪装成精确时间。

### 4.2 歌词管线

保留现有歌词源、缓存、`TrackIdentityCleaner`、`LyricsCandidateMatcher`、LRC 解析和显示选择逻辑。切歌或切换播放器时：

1. 取消旧曲目的歌词加载结果写回。
2. 立即更新歌曲信息与封面。
3. 清空旧歌词显示，显示“正在搜索同步歌词”。
4. 异步加载并匹配歌词。
5. 新歌词到达后短交叉淡入。

未找到歌词只影响歌词模块，其他模块继续工作。

### 4.3 歌词偏移快捷键

默认全局快捷键：

- `Ctrl+Alt+Left`：歌词提前 0.5 秒
- `Ctrl+Alt+Right`：歌词延后 0.5 秒
- `Ctrl+Alt+Down`：偏移归零

三项均可在设置中重新绑定。触发后，岛上短暂显示偏移值，不把歌词偏移作为可拖入模块。偏移在当前曲目会话内保留，切歌时恢复用户配置的全局默认偏移。

## 5. 模块系统

### 5.1 模块契约

`IslandModuleRegistry` 用模块类型标识创建视图与设置描述。每个模块声明：

- 类型标识
- 可否重复添加
- 最小/首选尺寸
- 支持的布局模式
- 所需快照字段
- 缺少能力时的降级状态
- 可配置属性

模块实例只保存类型、实例 ID、顺序和自身配置。渲染器根据布局模型创建视图。

### 5.2 v1.5 模块

1. **歌词模块**：当前句、下一句、翻译，继续尊重现有单双行设置。
2. **专辑封面模块**：读取 SMTC 缩略图；无封面时使用来源应用图标，再无图标时使用中性渐变占位。
3. **播放控制模块**：上一曲、播放/暂停、下一曲；不支持的按钮禁用。
4. **歌曲信息模块**：歌曲名、歌手、专辑，避免把元信息塞进歌词模块。
5. **播放进度模块**：进度条、当前位置和总时长；估算时间显示 `≈`。
6. **分割线模块**：允许重复添加、拖动、删除，可配置透明度和左右间距。

## 6. 布局模式

### 6.1 A：横向积木

模块按用户顺序在单行中排列。岛宽度根据模块首选尺寸和屏幕可用宽度计算；超过可用宽度时优先压缩可伸缩模块，仍不足则在设置编辑时提示用户移除或缩小模块，而不静默换行。

默认顺序：

```text
专辑封面 | 分割线 | 歌词 | 分割线 | 播放控制
```

歌曲信息和播放进度保留在模块库中，由用户自行添加。

### 6.2 C：双态展开

C 模式分别保存收起布局与展开布局：

- 收起默认只包含歌词模块。
- 展开默认包含专辑封面、歌曲信息、歌词、播放进度、分割线和播放控制。
- 鼠标进入岛屿有效区域 180ms 后展开。
- 鼠标离开且没有拖动、按下或菜单操作时，900ms 后收起。
- 用户与控件交互期间取消自动收起计时。

C 是独立扩展空间，后续版本可增加更丰富的模块和动效，不要求与 A 的横向结构保持同构。

### 6.3 A/C 配置隔离

A、C 各自保存模块列表、顺序和模块配置；C 进一步区分收起与展开布局。切换模式不复制或覆盖另一模式配置。

## 7. 直接编辑真实歌词岛

设置页不显示独立预览画布。用户进入“模块布局”设置时：

1. 屏幕顶部的真实歌词岛进入编辑模式并固定展开。
2. 自动收起、点击穿透和悬停透明逻辑暂时关闭；播放与歌词刷新继续运行。
3. 设置窗口显示模块工具箱，用户跨窗口把模块拖到真实岛。
4. 岛内模块也可再次拖动排序。

### 7.1 吸附和插入

- 拖拽进入目标插入点 18px 范围时显示发光吸附槽。
- 越过模块中线时，目标位置在该模块前后切换。
- 其他模块实时让位，并显示插入后的幽灵预览。
- 松开鼠标后只修改编辑草稿，不立即写入正式设置。
- 无效位置松开时，模块回到来源位置或模块库。

### 7.2 保存、取消和恢复默认

- 编辑过程使用深拷贝草稿。
- “保存布局”一次性替换对应模式配置并持久化。
- “取消”恢复进入编辑模式前的布局。
- “恢复默认”只修改草稿，仍需保存才生效。
- 设置窗口意外关闭等同于取消，避免保存半完成布局。

### 7.3 分割线

分割线与普通模块使用相同拖放、排序、删除和持久化流程。选中分割线后，设置页显示透明度与左右间距。连续分割线被允许，因为用户可能需要用不同间距构造分组；默认布局不会生成连续分割线。

## 8. 播放控制视觉与反馈

控制按钮默认只显示图标，不显示常驻背景：

- 默认：透明背景。
- 悬停：白色 14% 透明度的淡灰圆角矩形，圆角 10px，120ms 淡入。
- 按下：白色 24% 透明度，缩放到 92%，释放后 140ms 回弹。
- 禁用：图标透明度 28%，不显示悬停背景，并通过提示说明播放器不支持该操作。
- 每个按钮命中区域至少 40×34px。

该规范同时适用于 A 的控制模块和 C 展开布局中的控制模块。

## 9. 显示状态

- **无会话**：岛完全收回屏幕外，顶部中心保留不可见感应区。
- **开始播放**：岛滑入；A 显示完整配置，C 显示收起布局。
- **暂停**：保持当前展开状态 5 秒供用户恢复播放，随后收回；鼠标靠近顶部中心会重新唤出控制。
- **切歌/切播放器**：立即切换元信息并取消旧歌词写回，避免上一首歌词残留。
- **进入编辑模式**：岛固定展开，直到保存、取消或设置窗口关闭。

## 10. 设置模型与兼容迁移

现有设置继续保留。新增设置包括：

- 当前布局模式
- A 模式布局
- C 收起布局
- C 展开布局
- 锁定播放器标识
- 三个歌词偏移快捷键
- 全局默认歌词偏移

首次升级时从现有固定 UI 设置生成默认 A/C 布局。设置文件增加版本号；读取旧版本时执行一次性内存迁移并在成功保存后写入新格式。解析失败时备份损坏文件并恢复默认设置，不让应用无法启动。

## 11. 错误处理与降级

- SMTC 管理器初始化失败：显示一次可理解的状态提示并有限重试，保留托盘和设置入口。
- 会话在命令期间消失：命令返回失败但不崩溃，重新运行会话选择。
- 封面读取失败：应用图标或渐变占位。
- 时间轴缺失/冻结：内部计时并显示估算标记。
- 控制能力缺失：仅禁用对应按钮。
- 歌词源失败或无歌词：歌词模块显示状态，其他模块正常工作。
- 布局包含未知模块：跳过未知实例并保留原始配置数据，允许未来重新识别。
- 布局总宽度超限：编辑模式给出明确提示并阻止保存，不在运行时裁掉模块。

## 12. 测试与验收

### 12.1 自动化测试

- 会话选择优先级、播放器锁定和会话消失回退。
- 播放器来源识别与曲目信息清洗。
- 时间轴可靠、冻结、缺失、暂停、恢复和跳转。
- 控制能力映射和命令失败。
- A/C/C 收起/C 展开布局序列化及旧设置迁移。
- 模块插入、18px 吸附、跨中线换位、删除、重复分割线和取消回滚。
- 全局快捷键冲突检测、重绑定和偏移复位。
- 切歌时旧歌词异步结果不得覆盖新曲目。

SMTC、时钟和持久化都通过接口注入测试替身，使核心行为不依赖真实播放器即可重复验证。

### 12.2 五播放器人工矩阵

对 QQ 音乐、网易云音乐 UWP、酷狗音乐、Spotify、酷我音乐逐项记录：

- 会话识别和来源名称
- 标题、歌手、专辑、封面
- 歌词匹配和切歌
- 位置、时长、暂停/恢复、手动跳转
- 上一曲、播放/暂停、下一曲
- 不支持能力的禁用反馈
- 与另一播放器同时运行时的自动选择和锁定

### 12.3 UI 与回归测试

- A/C 独立布局和 C 双态布局。
- 从工具箱跨窗口拖入模块、吸附、排序、删除和分割线设置。
- 保存、取消、恢复默认和意外关闭回滚。
- 重启后布局、快捷键和播放器锁定恢复。
- 多显示器、100%/125%/150%/200% DPI 和屏幕边缘定位。
- 现有歌词源、缓存、翻译、单双行显示、托盘、开机启动和 Store 打包回归。

## 13. 完成标准

v1.5 可发布必须满足：

1. 五款目标播放器均完成实际运行记录，至少能正确识别当前曲目并进入歌词管线。
2. 播放器提供的控制能力可从岛上执行；未提供的能力有明确禁用状态。
3. 缺少时间轴的播放器可用内部计时持续滚动歌词，并能通过全局快捷键校准。
4. A/C 布局互不覆盖，C 收起/展开行为稳定。
5. 真实岛拖放编辑、吸附、分割线、保存与撤销通过自动化和人工测试。
6. 现有 Apple Music、歌词检索和 Microsoft Store 打包流程无回归。
