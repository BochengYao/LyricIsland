# 发布核对清单

发布线程负责区分“本地构建成功”“产物已生成”“外部平台已上传”“外部平台已发布”和“生产环境已验证”。前一状态不能替代后一状态。

## 发布前

- [ ] 明确基线提交、版本号、目标渠道和本次纳入的交接记录。
- [ ] 工作树只包含获准提交的文件；不纳入本地资产 WIP、证据快照、缓存或临时构建目录。
- [ ] 更新面向用户的 `CHANGELOG.md` 草稿，并完成对应质量验收。

## 本地构建与 MSIX

- [ ] 执行 `dotnet build LyricHover.sln -c Release`。
- [ ] 按发布脚本生成或复核 `publish/current` 与目标 MSIX；记录实际路径、版本和哈希。
- [ ] 解包或安装验证时，确认二进制与资产确为本次产物；不要以旧安装包替代当前验证。
- [ ] 区分“已构建”和“已发布”：本地 MSIX 产物不等于 Microsoft Store 状态。

## GitHub

- [ ] 核对分支、提交、标签、远端推送和附件哈希。
- [ ] 若创建 Release，确认草稿/已发布状态、下载资产和发布说明均可见。
- [ ] GitHub 演示资产不得与 Microsoft Store 的正式交付状态混淆。

## Microsoft Store

- [ ] 分别记录：已选择包、已上传、已验证、已提交审核、已发布。
- [ ] 未获用户明确确认，不能执行最终“提交审核”或发布动作。
- [ ] 核验 Store 身份与既有兼容标识，且不把 Partner Center 页面打开视为上传或提交完成。

## 官网生产

- [ ] 在 `website/` 运行 `npm run typecheck`、`npm run build:esa`、`npm run test:esa-api`。
- [ ] 部署后检查 `lyric-island.top` 的实际页面、路由、静态发现文件和响应，而非只依据构建或部署工具显示成功。
- [ ] 如有后台改动，使用授权会话复核权限边界，且不记录真实凭据。

## 完成

- [ ] 将 `CHANGELOG.md` 从草稿调整为实际发布记录。
- [ ] 在任务交接中记录产物、哈希、外部平台状态、生产验证和回滚点。

相关规则见 [既定决策](../coordination/04-DECISIONS.md) 与 [回归基线](../testing/REGRESSION_BASELINE.md)。
